# Архитектура и модель данных

Приложение состоит из статической страницы, чистой модели и слоя интерфейса. Сервер только отдаёт файлы по HTTP; данные задач не отправляются на него.

Состояние имеет версию формата 1 и два массива: `tasks`, `sprints`.

Задача: `id`, `title`, `description`, `priority`, `points`, `status`, `sprintId`.

Спринт: `id`, `name`, `start`, `end` в формате YYYY-MM-DD.

Идентификаторы формируются на клиенте. Связь задачи со спринтом проверяется. Перед сохранением или импортом состояние проходит общую валидацию. Текст пользователя вставляется через textContent, а не как HTML.

Переходы статусов разрешены между любыми колонками. При входе в progress проверяется общий лимит три задачи. Повторная установка того же статуса не считается дополнительной задачей.

localStorage хранит состояние для текущего адреса приложения. Экспорт JSON предназначен для резервирования и ручного переноса в другой браузер.
